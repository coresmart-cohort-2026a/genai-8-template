# DocuRAG

Rename this file to README.md when you submit. Every section is read by the reviewer; the brief for this project says what each one must contain. A section you cannot fill in yet is a section to write "not yet, because ..." in, not to delete.

## Demo

Unlisted YouTube link, two to three minutes, one take. Put it here, at the top.

## Overview

What this system does, for whom, in three sentences.

## Setup

From a fresh clone to a green test run: commands only, in order.

## Run

How to start it and how to call it. One example request and its response.

## API

Every route or entry point, its input schema and its output schema.

## Architecture

A sketch (a photo of paper is fine) and one paragraph: where the model, the retrieval, the tools and the state live.

## Design decisions

The choices you made and the alternatives you rejected, with the reason. This is the section a reviewer reads first.

## How I verified it

The tests, the golden set or benchmark, the numbers, and the one number you would watch in production.

## Known limitations

What it does not do, what breaks it, and what you would build next with another day.

## AI assistance

Three fields, all required: what you used an assistant for; what it got wrong that you caught, and how; what you wrote without it.
